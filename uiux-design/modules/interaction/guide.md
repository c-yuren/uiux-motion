# Interaction design
Map goal → affordance → action → immediate acknowledgment → state/outcome → next action. Keep discoverability, consistency, meaningful labels and predictable navigation. Functional state must not depend on an animation completing. Include keyboard, pointer, touch, stylus where relevant; no hover-only essential information. Focus order, focus-visible, restore focus after modal, Escape and accessible names; use native semantic controls first.
Model normal, pending, success, empty, error, disabled, offline, cancelled and stale response states as applicable. Avoid duplicate submissions and stale async overwrites; use request identities, cancellation and clear recovery. Optimistic UI requires rollback and honest feedback. Drag needs a non-drag alternative where applicable; allow cancel, bounds and keyboard. Test rapid repeats, interruptions, resize, input switching, back navigation, unmount and data changes. Motion follows user, not reverse. Preserve core workflows; confirm major flow changes. Use motion module for state choreography, visual for affordances and information for labels.

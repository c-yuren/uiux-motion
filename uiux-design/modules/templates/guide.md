# Template intelligence
Four layers: built-in design patterns, small editable local templates, optional external libraries, and newly validated reusable designs. Templates are optional building blocks, not mandatory first step. Start with intent and alternatives, search only if helpful, inspect provenance and license, extract useful structure, adapt semantic tokens, rework geometry and content, verify. Never copy proprietary code/assets without permission. External code is untrusted; inspect dependencies and licenses before authorized installation or execution.
Use [catalog](../../assets/templates/catalog.json) and CLI templates command for local assets. Local examples are deliberately small and editable. Search by role, framework, design intent, inputs, constraints and license. Providers in [providers](../../integrations/providers.json) are reference starting points, not preinstalled connectors or a guarantee of current availability/license. Agent native web search is sufficient; optional API/MCP only when available. Distinguish inspiration-only from reusable code; no automatic downloading or execution. Offline fallback: built-in patterns and original design.
For a generated template, record ID/version, purpose, platform, source/license/permission, dependencies, accessible fallback, validation evidence and constraints; store project-local until user authorizes sanitized sharing. Avoid leaking private material. Template preview must not mutate production UI by default.

# Routing and progressive loading
Modes: auto, design, visual, motion, information, interaction, audit, refine, enhance, repair, explore, template, system, preview, validate, learn, resume. A specialist mode narrows scope; audit does not modify product code. Refine defaults Deep for full scope; Auto otherwise. Quick/Balanced/Deep/Extreme set exploration and validation budget, not a waiver of mandatory gates.
| Task | Lead | Load also when relevant |
|---|---|---|
| redesign icon or compact status | visual | information, creativity |
| chart or dashboard | information | visual, interaction, motion for changing data |
| animated product display or ambient effect | visual | motion for timing/continuity, creativity |
| sidebar transition, gesture | motion | interaction, visual if geometry changes |
| form flow / feedback | interaction | information, motion, visual |
| existing app full UI/UX | shared audit | all relevant specialists |
| visual report, slide, specification diagram | visual | information; read media extension |
| template research | templates | creativity and relevant domain |
Use one task owner and one registry. Assign non-overlapping source ownership if parallel agents are available; integrate once, run shared regression. If no specialist tooling, use design reasoning and mark unverified. Never assume a host supports automatic skill invocation or GUI.

# Configuration inheritance and isolation
Optional preference files: user home/.config/uiux-design/preferences.json (portable convention including Windows home) and explicit project root/.uiux/preferences.json. No automatic creation. Use one project root per task; do not scan siblings or ancestor projects. Existing .uiux/config.json, registry, design system, task-state, locks and legacy .motion are unchanged. Existing config remains authoritative for project task defaults where explicitly set; preferences provide soft defaults only. If existing project settings conflict with preference suggestions, honor explicit project design constraints and disclose conflict. 
Merge supported fields individually: skill defaults < global preferences < project preferences < explicit task overrides. Defaults activation.mode auto, maxAutoLevel 4, style adaptive, quality premium, depth auto. Activation mode auto/manual/disabled controls automatic invocation; force/off for a single task is explicit and not persisted. Host policy may still restrict invocation. Preference fields never grant authorization. Unknown fields are ignored by the resolver, not propagated into decisions. Validate known values; malformed settings fail explicitly. Task authorization, project constraints, locks, accessibility, actual medium and user request outrank soft defaults. No global writing of project data. 
Keep project tokens, contracts, audits, captures, source, credentials and decisions in project storage; shared experience opt-in only, sanitized and validated. A global preference should be explicitly chosen by user, not inferred from one project. For cross-agent sync distribute the same skill version and intentional preference file, not .uiux or secrets; sync project state only between agents working on that same project. No automatic sync or network access.
The optional CLI reads only named task JSON, global preferences and the explicitly selected root's preference file. Default root is current working directory; invoke from actual project root or pass --project-root. It does not create files. For separate projects resolve separately. See assets/defaults/preferences.example.json and activation-task.example.json.

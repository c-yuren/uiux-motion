# Unified design registry and audit
Discover from routes, component/DOM/accessibility trees, source, actual navigation and state fixtures. Inventory pages, sections, components, graphics, data encodings, ambient effects and each distinct interaction/state transition, including missing opportunities. Record unreachable scope, roles, viewport, input, locale and data boundaries. Never trigger destructive real operations.
One entity per stable semantic component or region in a specific context; multiple checks per dimension and subject. Example: a sidebar has visual layout check, information grouping check, motion open/close check, interaction keyboard/focus check. Shared component fixes may be centralized, but verify each distinct context. Multiple actions can share the same entity ID, never collapse all events into one check.
Cycle: observe baseline → assess purpose and issue → explore alternatives → keep/refine/add/replace/simplify/repair/remove → approve if required → implement → validate → record evidence. Manual review shows current and candidate render/behavior, rationale, costs and decision, then waits. Audit mode is read-only for product code.
Incremental: map modified files, semantic tokens, routes and dependencies to affected entities; invalidate all their checks conservatively; unknown dependency means widen scope. Discover new items and record removed ones, do not silently delete history. Full audit includes visual, information, motion, interaction as applicable. Mark irrelevant dimensions with rationale rather than manufacture work.
Report discovered entities, checks by dimension/status, reviewed and verified checks, unknown scope and failures. A zero-item inventory or unknown scope never equals full pass. A successful CLI report reflects recorded statuses only, not actual design quality.

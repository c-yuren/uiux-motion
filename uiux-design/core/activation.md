# Global installation and adaptive activation (1.2.1)
Install the skill once per host discovery mechanism; use native metadata-based discovery first. Do not load the entire skill into always-on instructions. Global means the capability is available, not that every task invokes it. Host agent classifies relevance before reading optional modules. No background daemon, mandatory MCP or hook is installed. Optional activation CLI accepts structured inputs; it is not a natural-language classifier and cannot force hosts to invoke a skill.
| Level | Use | Loading |
|---|---|---|
| L0 Inactive | backend-only, unrelated logic/data tasks | no skill body |
| L1 Awareness | indirect or uncertain UI impact | entry principles; inspect impact, escalate if necessary |
| L2 Targeted | named component, visual or motion change | relevant profiles, intent/stage and specialist modules |
| L3 Integrated | feature or page with multiple dimensions | relevant specialists, proportional contract and verification |
| L4 Comprehensive | full product design or audit/refine | all applicable dimensions, registry, baseline, complete declared scope |
These are relative coverage levels, not token percentages or replacements for execution depth (Quick/Deep etc). Choose by actual task; escalate if UI impact appears during a feature/bug fix. No unrelated UI work. A cap below required scope must be disclosed; do not claim full audit or waive quality gates. Explicit user opt-out overrides auto; explicit invocation may override automatic mode/cap, never scope, locks, safety or authorization. A host-level disabled skill may need manual re-enabling.
## Avoid duplicate invocation
Check already-loaded session/task context, reuse the same task owner and evidence, load only new relevant modules. If another design skill is active, coordinate ownership and prioritize explicit project conventions, avoid repeated audits and conflicting changes. Same-name copies can be discovered differently by hosts; choose one effective installation per host, compare versions and disable duplicates after verification. Never delete existing user configuration automatically.
## Configuration
Read core/configuration.md for preferences. No global preference grants product-write permission, suppresses required gates or alters project locks. L0 does not need to read project design data. For L1 no registry or contract unless scope changes. For L2–L4 follow existing context routing, authorization and quality.

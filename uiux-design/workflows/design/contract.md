# Design Contract
A handoff artifact, not a substitute for user authorization. Create .uiux/tasks/<task-id>/design-contract.json for significant work or separate-agent handoff, using schemas/design-contract.schema.json and assets/defaults/design-contract.example.json. Simple one-line fixes can use a short note. 
Record task ID, revision, context, scope/in-scope and out-of-scope, baseline revision, design intent, visual/information/interaction/motion decisions as applicable, tokens, component and responsive/state requirements, assets/provenance, prototype refs, acceptance criteria, locks, decisions and approval status, open issues, and next action. Use precise values/units where design requires; distinguish illustrative from approved. Contract status draft/ready/approved/superseded: ready means internally specified, not human approval. High impact needs explicit approval of that decision before production; user locks are not waived by contract status.
Produce receives contract and verifies version, current project revision, approved/locked decisions, unresolved issues and authorization. Record deviations and reasons; local non-conflicting changes may be allowed by scope, high-impact changes loop back to Design and require approval. Preserve earlier versions. Contract metadata validation is not proof of rendered fidelity; use real tests. Never include secrets or private external data in shared files.

# Design stage
Purpose: make decisions and specify behavior, not change production code. Study product/context, current constraints, information and user goals; explore alternatives (importance-based), create sketches/wireframes/HTML/SVG/interactive prototypes in explicitly isolated locations. Do not install dependencies or edit product files merely for a prototype. Inspect actual renders if possible. Define chosen structure, tokens, content, state matrix, interactions, motion, responsive variants, accessibility, asset rights and criteria. A compact design note is enough for simple tasks; significant redesign, separate stages or handoff use contract.md. Record rejected alternatives, unresolved issues and approval requirements. Stop if Design Only; do not turn approval of a mockup into automatic implementation permission. If user asked for editable finished visual asset, create that requested deliverable without changing unrelated production project.
